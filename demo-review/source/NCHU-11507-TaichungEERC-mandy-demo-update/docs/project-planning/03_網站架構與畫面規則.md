# 網站架構與畫面規則

> 目前採用的網站地圖為「總覽＋三區細圖」：公開網站、一般與承辦共用的學校工作區、系統管理員工作區。對應圖稿位於 `../diagrams/sitemap/`。

## 一、三個區域與共用版型

| 區域 | 使用者 | 主要構成 | 說明 |
| --- | --- | --- | --- |
| 公開網站 | 訪客，也可由已登入者瀏覽 | `nav` 選單、可能位於 `header` 的跑馬燈、`main` 內容、`footer` 聯絡資訊 | 以使用者提供的公開網頁框架圖為視覺參考。 |
| 學校工作區 | 一般學校與獲授權的承辦人員 | `nav` 選單、麵包屑、身分顯示區、`main` 工作內容、`footer` | **只有一個學校工作區**；承辦權限增加競賽承辦選單及檢視。 |
| 系統管理員工作區 | 系統管理員 | 管理員 `nav`、麵包屑、身分顯示區、`main` 管理內容、`footer` | 管理員設定與審查集中於此。 |

原框架圖的顏色語意：橘色為選單／nav、紫色跑馬燈可能屬 header、藍綠色為 main、土黃色為 footer、綠色為登入者身分與權限顯示區。顏色是畫圖語意，不限定最終 CSS 色票。

## 二、Vue 操作方式

- 預計使用 Vue 前端與 Vue Router。點選工作區 `nav` 後，在保留共用版型的情況下切換 `main` 中的檢視，使用者感受接近不整頁重新載入。
- 網站地圖以**可獨立導航的檢視／路由**為主要節點，不以每個輸入框、按鈕建立一個節點。
- 同一檢視中的搜尋欄位、文字輸入、儲存／送出／匯出按鈕，標為**功能註記**。若操作開啟獨立路由、詳細頁、彈窗或外部視窗，需在圖上明確區分其類型。
- `main` 可依權限呈現不同內容；不得以「畫面上看不到」取代 Laravel API 的權限及資料歸屬檢查。
- 例：公告列表是檢視；公告詳情因有獨立分享網址是另一檢視；公告編輯若採獨立路由也列檢視，表單欄位與按鈕列功能註記。實際路由命名待程式設計時確定。

## 三、區域內容草案

### 公開網站

- 首頁／跑馬燈、最新消息列表及獨立詳情網址、中心與工作人員資訊、人才資料、下載、FAQ、好站連結、全站搜尋、雙語切換、聯絡資訊。
- 競賽公開資訊、依設定公開的出場序與得獎名單；參賽個資、審核意見及補件內容不得因公開頁而直接揭露。
- 教學資源搜尋，以及經管理員設定可公開的成果照片／計畫內容。
- 營隊資訊與訪客免登入報名。

### 共用學校工作區

- 一般學校功能：學校資料、指定調查表填報與狀態、教學資源／成果照片上傳、競賽查看與報名／補件、計畫填報與經費概算。
- 承辦選單：僅在指定人員具承辦權限時顯示；處理所屬學校承辦的競賽建立、設定、報名審核、抽籤、成績與公告相關操作。
- 承辦人員仍使用**同一份**一般學校填報、上傳、報名畫面；不複製成承辦專用頁。
- 身分顯示區可呈現登入者資料、所屬學校、權限、登入時限及登出；是否需要可點的「身分切換」控制尚未核定，目前不要求切換帳號或工作區。

### 系統管理員工作區

- 帳號、學校及承辦人授權；學校班級數匯入；網站頁面、公告、跑馬燈、人才、下載、FAQ、連結、雙語及搜尋設定。
- 調查表題目、期限、指定填報學校、查詢與匯出；資源／照片類別與上傳限制、打包下載。
- 競賽所需自訂欄位、權限設定；管理員代承辦操作未決，不預設開通。
- 計畫專案、欄位及公開範圍設定、經費檢視、兩階段審查；營隊設定、匯出與活動結束後刪除該場報名資料。

## 五、仍待確認

- 公開網站是否需要自助「註冊」頁、登入入口的確切文案。
- 各功能使用獨立路由、抽屜或彈窗的實際 UI 決定。
- 公開資源、照片、計畫內容的審核與發布時點。
- 雙語缺少翻譯時的回退文字及每頁切換方式。
