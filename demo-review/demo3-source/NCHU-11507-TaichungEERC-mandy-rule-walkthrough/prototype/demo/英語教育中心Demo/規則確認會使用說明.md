# Demo 3 規則確認會

雙擊 [規則確認會.html](規則確認會.html)；或用本機網頁伺服器開啟 `index.html?walkthrough=1`。畫面右側會出現十一步走查工具，點「打開本步畫面」切換到 Demo 3 對應角色與頁面。右側選項只記錄討論或驗證結果，不會改動 Demo 原有判斷。此版筆記與 Demo 2 分開保存，先前若有筆記，請先從 Demo 2 匯出 Markdown。

建議由四位成員輪流讀本步任務、親手操作、回答討論題，遇到不合理行為就寫「看到的問題」與「希望的行為」。可先跳過不確定題目。討論紀錄會嘗試存於本機瀏覽器；若瀏覽器阻擋儲存，仍可在關閉前下載 Markdown。

**結束時先按「複製回饋摘要」或「下載 Markdown」**，把摘要貼到 Codex 對話。Codex 才能依 PDF、既有決議與走查建議分類，協助下一輪修改。筆記不會自動傳給 Codex，也不會上傳網路。請勿填入真實學生或聯絡人的個資。

## 真正可操作與尚未實作的界線

- 可操作：一筆示範案件由學校預覽資料、確認送出、承辦要求補件、學校重送，到承辦核准；兩角色看到同一筆當前狀態。
- 展示草稿：承辦競賽資訊、組別、名額、班級數與三段時窗的輸入。它們**尚未限制核心案件報名**，因此這一輪只能確認操作和討論規則，不能用來證明名額或時窗的正確性。
- 承辦回饋示例：競賽須知與評分標準必填；可沿用一筆歷史設定、送出前確認、編輯可選名額草稿、查閱預建的已結案紀錄。正式名冊畫面只列核准案件。歷史設定與名額草稿只存於本次頁面，**未套用正式規則或限制核心報名**。結案操作尚未定案。
- 預建情境：出場序、成績與公告，**沒有連到剛才的報名案件**。名冊只有畫面預覽，沒有輸出 PDF／Excel／Word。
- Demo 案件存在頁面記憶體，重新整理會回到初始狀態；討論紀錄若本機儲存可用，重新整理後仍在。工具內「只重設 Demo 案件」不刪討論紀錄。

## 這次小組要帶回的成果

1. 每一步的選項與理由，未選者維持待決。
2. 可重現的問題：在哪一步、按什麼、看見什麼、預期什麼。
3. 下一輪要先改的流程，與需要外部範本或業主確認的規則。

本工具只協助確認 Demo 3 與規則。PDF 需求範圍仍以 `docs/requirements/需求書原文.md` 為準；走查選項未經小組正式確認前，不能直接變成 migration 或 API 正式規格。
