# PDF需求與架構核對（2026-09-29）

## 依據與優先序

主要依據：使用者提供的《臺中市英語教育資源中心網站建置委託資訊服務案需求說明書》，共 10 頁。以下頁碼為 PDF 頁序，與第 2 頁起的頁尾頁碼相符。

輔助依據：全功能泳道圖整合.svg，以及 4 張網站架構截圖（公開網站、一般學校工作區、競賽承辦工作區、系統管理後台）。頁面主要名稱可辨識；部分小字、被 NO… 貼紙遮住的內容，以及紅藍線的意義未據此定案。P0/P1/P2 是圖上的標籤，不能當作 PDF 的優先序或刪除需求的依據。

其他網站只供風格參考。未新增學生登入、單字練習、測驗或影音學習系統。

## 原型的定位

明天報告：前端模擬。兩週後：後端、資料庫與 API 整合目標；不等於 PDF 契約所載整體履約完成。PDF 第 2 頁原案日程為 115 年 3 月底建置上線、4 月底教育訓練與驗收；這與本次專題期限不同，不能混用。

## 架構圖與PDF的差異／待決

1. 公開圖的「註冊」：PDF 沒有一般訪客自助註冊，也沒有學生登入。原型只提供學校/管理員登入入口；不新增自行註冊流程。
2. 公開圖的「行事曆」：PDF 未明列，先不新增功能；若團隊要保留需明確確認用途與範圍。
3. 公開競賽導覽下的「報名、上傳」：入口可展示於公開資訊，但操作必須進入學校登入後的工作區，不表示訪客可替學校送件。
4. 一般學校/承辦分兩张圖可以表示功能分組，不必然表示強制切換身分。團隊已確認同一工作區顯示兩組選單（A 方案）。
5. 泳道圖「教育局同仁或本校人員→自動取得管理員」超出 PDF 明文。PDF 說明既有管理員的登入方式，並不代表登入者因任職單位就自動授予管理員。
6. 調查對象：PDF 為指定教育階段學校；泳道圖為逐一指定學校，是否同時支援兩者待確認。
7. 首頁「我的待辦」與管理後台「待處理事項」在截圖旁有未完成註記；可作 UX 建議，不當成 PDF 明列獨立功能。
8. 圖上的「師資介紹」與人才/組織圖可對應中心介紹、人才資料庫，不新造學生功能。

## 正式交付仍有的非功能要求

- 第2頁：RWD、前台 AA 無障礙標章（保固期內取得）。原型不是標章驗收結果。
- 第6–7頁：指定虛擬 Linux 環境、效能測試、HTTPS及憑證、操作手冊、原始碼、測試報告、技轉與文件。
- 第6–10頁：一年保固、教育訓練/影片、資安檢核與測試、相關維運義務。以上是需求書項目紀錄，不表示原型已履行或取得認證。

## 開發順序建議（不是新增範圍）

先確認角色權限與学校資料、時窗、名額/組別、報名欄位與狀態，再建立資料庫/API契約；各模組逐條對照上表。不能用目前最小表單反向定義正式SQL。

## 2026-09-30 承辦端補齊

新增承辦工作台、競賽建立／編輯、組別與報名設定、報名資料／報表、出場序抽籤、成績與序位、得獎公告入口。既有報名審核保留。

競賽草稿可編輯並儲存在記憶體，欄位涵蓋 PDF 第 4–5 頁的資訊、組別、班級數、參賽欄位、兩類教師上限及三段時窗。設定不套用核心案例，尚無多競賽新增及正式設定 API。報表只預覽、抽籤和成績使用固定情境；未產出正式文件或執行演算法。公開欄位及名次目前固定。

承辦學校本校案件頁展示空狀態，尚未擴充多校報名表；一般學校 A 的完整報名／補件流程可操作。

## 2026-10-02 小組回饋原型補充

一般學校送出競賽報名前新增資料摘要預覽、返回修改、確認送出及完成提示。承辦競賽須知與評分標準必填，新增歷史設定套用、儲存前確認、可選名額條件草稿與剩餘量示意。報名摘要與僅核准案件的正式名冊預覽分開；已結案頁只查閱預建歷史示例。

上述仍只是一筆假案件的前端原型：歷史設定在重新整理後還原，名額顯示不阻止報名，結案方式與後續修改規則仍待團隊確認，名冊未匯出 Excel，報名表、授權書及評分表也未產生正式檔案。對應 PDF 第 4–5 頁 REQ-038、041、045–046，不得以這些畫面判定正式需求已完成。
