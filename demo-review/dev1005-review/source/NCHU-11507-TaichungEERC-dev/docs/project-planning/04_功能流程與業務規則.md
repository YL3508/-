# 功能流程與業務規則

> 按需求書第 2–6 頁「貳、專案需求」排列。每節區分需求書原案、目前專題決議與待確認規則。全功能泳道圖是流程總覽；此檔供畫細圖、設計 ERD／API 及測試分支時引用。原 P0／P1／P2 僅是先後參考，不用來排除 10/13 的全模組目標。

## 1. 註冊／登入、身分與權限（需求書第 2 頁「三、功能需求（一）」）

**原案**：教育局同仁任管理員可用教育局 Open ID；非教育局或學校人員有統一帳密路徑；一般與承辦學校使用教育局 Open ID；管理員可從後端設定學校承辦身分。

**已釐清**：學校人員個人透過教育局 Open ID 登入，資料與權限歸戶學校；本校人員不因本校身分自動取得管理員權限。教育局判定管理員資格，並為受指定的非教育局、非學校人員統一設定帳密。管理員先指定承辦學校，再逐一授權該校指定人員；承辦者保有一般學校功能。此段取代舊版「本校人員登入即取得管理員權限／由管理員設定帳密」的說法。詳細判斷見 [02_帳號角色與權限規則.md](02_帳號角色與權限規則.md)。

**流程判斷**：登入是否成功、所屬單位是否可辨識、是否具管理員／承辦角色、是否有權存取特定學校或競賽資料。失敗分支須顯示原因；身分不明時不得自動升權。

**待確認**：首次登入是否需要補齊資料、學校自助註冊是否存在、Open ID 正式介接欄位、承辦撤權與離校處理。

## 2. 網站呈現功能或數據（需求書第 2–3 頁「（二）」）

| 功能 | 需求書要點與角色 | 流程／資料注意 |
| --- | --- | --- |
| 系統、學校與帳號管理 | 管理員設定網站分頁、學校資料、帳號及承辦角色。 | 競賽班級數由管理員從後台匯入；匯入格式及重複資料處理待確認。 |
| 跑馬輪播 | 管理員可放多項畫面；外部網址可由圖片點擊開新頁。 | 啟用、排序及上下架方式待確認。 |
| 最新消息 | 標題、內容、類別、關鍵字；可附多連結／圖片／檔案、設定起訖時間，且每則有獨立網址。 | 設定公開後，訪客可讀；逾期或未公開資料須按規則控制。 |
| 組織與中心成員 | 工作組織圖及成員圖片、姓名、職掌、聯絡方式等。 | 管理員編輯、公開頁呈現。 |
| 人才資料 | 管理員新增類別並設定哪些個人欄位公開。 | 個資公開範圍需在資料欄位與 API 中一致。 |
| 檔案下載 | 欄位近似消息，可多檔／連結、分類及設定起訖。 | 下載檔案的公開期限及替換版本待確認。 |
| FAQ 與好站連結 | 管理員設定問答與外部連結；連結另開分頁。 | 圖片或說明文字依需求書支援。 |
| 統計、聯絡、搜尋與雙語 | 當前／本日／本月／本年瀏覽人數、中心聯絡資訊、全站搜尋與熱門字；雙語欄位有填才可呈現。 | 統計口徑、搜尋範圍及雙語缺值處理待確認。 |

站務管理與公開瀏覽屬不同操作；公開頁不得顯示未設定開放的資料。

## 3. 線上填報、教學資源與成果照片（需求書第 3–4 頁「（三）」）

### 3.1 線上填報

1. 管理員新增調查表、細項題目、起訖時間，**逐一指定**可填報的學校；指定對象可為一般學校，也可為兼承辦的學校。
2. 系統依指定對象與時間窗提供入口。未被指定、期限未到或已過期時不得填報；錯誤提示文案待設計。
3. 被指定學校填寫並送出；承辦人員如所屬學校被指定，可從共用學校功能操作，不需要第二份承辦填報頁。
4. 管理員檢視未填報名單、各校答案與統計，依原案匯出質性 Word、量化 Excel。

**待確認**：一校多人填寫時的最終提交規則、送出後能否修改、是否需要人工審核或退回、題型與統計口徑。泳道圖中的「檢核欄位／待確認」不得自動當成已核定審核流程。

### 3.2 教學資源與成果照片（共用上傳流程）

1. 管理員設定類別、細項、檔案限制及說明欄位；管理員也可上傳。
2. **所有已註冊學校**，包含一般與兼承辦學校，均可在同一學校工作區上傳。
3. 共用流程可整理成「選擇資料類型 → 選類別／細項 → 上傳檔案與文字 → 系統檢查 → 儲存」。資料仍須區分`教學資源`與`成果照片`，因檔案性質、類別細項及限制不同。
4. 教學資源支援關鍵字搜尋；管理員可依全部、勾選或時間範圍打包檔案下載。照片的檔案大小與說明字數限制須可設定／檢核。
5. 公開頁是否顯示，以及需要審核後才公開的時點，**尚待確認**；不能因上傳成功就推定即時公開。

合併的是**操作流程**，不是把兩類資料混成同一種內容；ERD 與 API 必須保留類型及各自欄位／限制。

## 4. 競賽設定、報名、審核、抽籤與成績（需求書第 4–5 頁「（四）」）

### 4.1 授權與建立

- 管理員指定承辦學校，逐一授權該校指定人員承辦角色；授權檢查在帳號流程及競賽入口都要出現。
- 承辦指定人員建立競賽，設定名稱、時間、地點、須知、評分標準、學校報名人／組數上限與組別。
- 管理員依競賽需求可**新增**參賽者報名欄位、指導老師欄位與行政支援老師欄位。承辦學校設定每場使用的欄位、開放項目及人數上限；管理員代建賽仍待確認。
- 系統利用管理員匯入的學校班級數判讀可報組別。缺少班級資料、資料過期或判組邊界的處理待確認。

### 4.2 報名與資料時窗

1. 學校人員查看競賽及可報組別，以一般學校權限填參賽者、曲目／預計演出時間、指導及行政支援老師資料，送出報名。
2. 系統檢查可報組別、報名時間、必填欄位及名額；通過才收件，未通過則顯示具體原因。達上限不得新增報名。
3. 原案分**報名、修正資料、上傳報名資料**三段時間；第三段不開放新增報名或修正，只可上傳資料。各段是否可重疊及例外權限待確認。
4. 報名後系統依需求書產出報名表暨授權書 PDF、參賽名冊 Excel、評審評分表 Word；授權書公版格式由教育局提供。產檔觸發時點及重產版本待確認。

### 4.3 資格審核與補件

1. 承辦指定人員檢視所屬學校承辦競賽的報名與附件，填寫審核結果及意見。
2. 審核結果分**通過**與**需補件**。需補件時，參賽學校登入查看意見並重傳；系統將其標為**待審查**，回承辦者再審。圖上用綠色標通過，紅色標未通過／需補件及返工路徑，箭頭與文字不重疊。
3. 審核意見、參賽個資及補件內容不對外公開。是否同校或同人可以審自己的報名，仍待確認。

### 4.4 抽籤、評分、名次與公告

1. 系統按組別對報名資料隨機抽出場序；承辦者設定是否於公開網站公告。
2. 承辦者手動登錄各評審成績；系統依各評審成績產生序位，以序位合計由小至大排序並產出供簽名的成績總表。
3. 承辦者手動登錄競賽名次；經勾選應公開欄位後，公開頁按名次顯示得獎名單。草稿與正式發布須區分。
4. 評分規則、同分處理、重抽與發布確認流程待確認，不應僅憑圖稿自行補成核定規則。

## 5. 計畫設定、填報、經費與兩階段審查（需求書第 5 頁「（五）」）

1. 管理員開立計畫專案，設定填報內容、上傳欄位、期間及各欄位／檔案是否可於公開頁瀏覽。
2. 各校在期限內填計畫資料、上傳文件，填寫經費概算的細項金額、總額與備註。兼承辦學校使用同一份一般學校計畫功能。
3. 系統彙整數據，協助管理員看金額編列；欄位缺漏與加總異常可提示，但異常是否阻擋送件待確認。
4. **計畫審查者就是系統管理員**。第一階段結果為通過／不通過／修正後通過；第二階段為通過／不通過；兩階段均可填意見。
5. 管理員可依填報資料匯出 Excel。前台僅呈現被設定可公開的內容與檔案；實際公開時點待確認。

**待確認**：兩階段進入條件、修正後通過的補正流程、學校查看意見與重新上傳期限、審查通知方式。

## 6. 營隊活動報名（需求書第 6 頁「（六）」）

1. 管理員設定活動名稱、場次、調查欄位、起訖時間、注意事項、正取及備取名額。
2. 訪客免申請帳號密碼即可報名；系統應檢核重複報名、期限與剩餘名額，額滿時顯示停止報名。重複判定欄位及個資保護待確認。
3. 管理員匯出報名資料 Excel。活動結束後可從後台刪除**該場次所有報名資料及紀錄**；不能將需求書解讀成直接刪除活動本身。
4. 刪除前的確認、授權與備份／留存規則待確認；涉及實際資料時須依專題及資料保護要求處理。

## 7. 全站共通要求（需求書第 2、6 頁）

- 公開前台需響應式設計；原採購案另有 AA 無障礙標章要求，專題報告須區分「參照要求」與「已取得標章」。
- 雙語欄位由管理員設定；填寫雙語內容時網站切換後可呈現。未填時如何顯示待確認。
- 所有流程中的綠／紅分支及「待確認」註記，是**流程表達方式**；未有明確規則的時限、審查與通知不可假定為需求書明載。
